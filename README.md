# ARAH — Adaptive Recovery & Achievement Hub

**Stay Productive, Stay Human** · TECHCOMFEST 2027 · Smart Lifestyle & Digital Wellbeing.

Phase 2 is a modular monolith foundation for a two-person team. Module pages are public placeholders. Authentication, registration, admin operations, and private wellbeing records are not implemented. Backend auth dependencies reject access until verified identity is implemented.

## Prerequisites

- Windows PowerShell, Git, Node.js LTS (verified: 24.17.0, npm 11.13.0).
- Python 3.12+ (verified: 3.12.16). The Windows Store `python` alias may not be a usable interpreter; use a full interpreter path when necessary.
- PostgreSQL (verified: 18.7). A regular PostgreSQL installation is recommended for ongoing development. Docker is optional and is not required by this project.

The frontend uses React 19, TypeScript 7, Vite 8 and Tailwind 4 with its Vite plugin. Dependency versions are pinned in `frontend/package.json` and `package-lock.json`; backend constraints are in `backend/requirements.lock.txt`.

## Installation

From the repository root:

```powershell
python -m venv backend/.venv
Push-Location backend
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
Pop-Location
Push-Location frontend
npm ci
Copy-Item .env.example .env
Pop-Location
```

Do not overwrite an existing `.env`. Activate the virtual environment if desired, or use its executable directly as above.

## Database and environment

Create a PostgreSQL login and application database using an administrator account (for example, in `psql`):

```sql
CREATE ROLE arah LOGIN PASSWORD 'replace-with-a-random-local-password';
CREATE DATABASE arah OWNER arah;
CREATE DATABASE arah_test OWNER arah;
```

Set `backend/.env`:

```dotenv
DATABASE_URL=postgresql+psycopg://arah:YOUR_URL_ENCODED_PASSWORD@localhost:5432/arah
FRONTEND_ORIGIN=http://localhost:5173
```

Set `frontend/.env`:

```dotenv
VITE_API_BASE_URL=http://localhost:8000/api/v1
```

`DATABASE_URL` is required; startup fails on missing/invalid configuration. Use the `postgresql+psycopg` driver scheme. URL-encode special characters in credentials. Only public API configuration belongs in `VITE_` variables: these are included in the browser bundle. Git ignores local environments and database files. Production requires a separate deployment/secrets/CORS review and a least-privilege runtime database login.

Run migrations from `backend`:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m alembic current
.\.venv\Scripts\python.exe -m alembic check
```

Migration `0001_users` creates only `users`: UUID primary key, unique non-null email, nullable password hash/display name, constrained `user`/`admin` role with `user` default, onboarding default `false`, and timezone-aware timestamps. A PostgreSQL trigger updates `updated_at` for SQL and ORM writes. UUID values are generated by the SQLAlchemy model; raw SQL inserts must supply an ID. No user data is seeded.

The four final Phase 1 ERD images have now been inspected and preserved under `docs/database/erd/`. The [22-table reference and users comparison](docs/database/PHASE_1_ERD_REFERENCE.md) distinguishes visible constraints from unspecified details. Users column names, base types, primary key and unique email match the diagram. Existing varchar lengths, defaults, role check, and stricter onboarding/timestamp nullability are documented implementation decisions; the image does not specify their complete DDL. No schema change was required, so the applied migration was preserved unchanged. Future confirmed changes require a new migration. The other 21 tables remain unimplemented.

Default user timezone is **Asia/Jakarta** in both the frontend preference context and backend settings; database connections for the application and Alembic explicitly use **UTC**. `timestamptz` stores instants; convert only for presentation. The future `user_preferences` table has not been created. To make the database default UTC for other SQL clients too, an owner can run:

```sql
ALTER DATABASE arah SET timezone TO 'UTC';
ALTER DATABASE arah_test SET timezone TO 'UTC';
```

These defaults are already applied to this workspace's databases and take effect for new connections. They do not change the operating system timezone. Restart an older backend process if it was launched before the configuration update. A UTC instant `2026-11-21T18:30:00Z` displays as 22 November 2026, 01:30 in Jakarta; date-only fields remain calendar dates.

## Start development

Terminal 1, from `backend`:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Terminal 2, from `frontend`:

```powershell
npm run dev
```

Open [ARAH](http://localhost:5173/app/dashboard) and [Swagger UI](http://localhost:8000/docs). Exact CORS origin is `http://localhost:5173`; using `http://127.0.0.1:5173` is a different origin. Stop servers with Ctrl+C.

| Endpoint | Behavior |
|---|---|
| `GET /api/v1/health` | `200 {"status":"ok","service":"ARAH API"}` |
| `GET /api/v1/health/db` | Executes `SELECT 1`; `200 {"status":"ok","database":"connected"}` or generic `503` on SQL connectivity failure |
| `GET /docs`, `GET /openapi.json` | Interactive API docs and schema |

API and database states are checked independently with a five-second browser timeout, cancellation on unmount and a retry button. Database connectivity does not imply migrations are current: use Alembic checks too.

Public routes: `/`, `/login`, `/register`. User preview: `/app/dashboard`, `/app/tasks`, `/app/pulih`, `/app/rest`, `/app/nourish`, `/app/pantry`, `/app/assistant`, `/app/reports`, `/app/settings`. Admin preview: `/admin/dashboard`, `/admin/users`, `/admin/recipes`, `/admin/ingredients`, `/admin/prices`. These pages contain no protected data. Do not expose private APIs until backend authentication and ownership checks exist.

## Tests and verification

```powershell
# From frontend:
npm run build
npm test
npm audit --audit-level=moderate

# From backend:
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe -m pip check
```

Four database tests skip unless `ARAH_TEST_DATABASE` is set. To run them, set `DATABASE_URL` to a **dedicated** migrated database, such as `arah_test`. Existing environment variables override `.env`. Tests roll back their inserted rows. The complete suite currently has 23 frontend tests and 9 backend tests, including timezone and ERD/schema checks.

```powershell
# From backend, using your own local credentials:
$env:DATABASE_URL='postgresql+psycopg://arah:YOUR_URL_ENCODED_PASSWORD@localhost:5432/arah_test'
$env:ARAH_TEST_DATABASE='1'
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m pytest -q
# Reversibility test: ONLY on an isolated test database. This drops users.
.\.venv\Scripts\python.exe -m alembic downgrade base
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m alembic check
Remove-Item Env:DATABASE_URL
Remove-Item Env:ARAH_TEST_DATABASE
```

Optional headless Chrome smoke test, from root with all services running:

```powershell
npm install --prefix .tools/browser --save-exact playwright
node scripts/browser-smoke.cjs
```

Set `CHROME_PATH` if Chrome is installed somewhere other than the script's Windows default. Checks use real Fetch/CORS/API/PostgreSQL, test 390px/1440px layouts, theme/language persistence, Swagger, overflow and browser errors. Screenshots are saved to `docs/reports/evidence/`. This is a smoke test, not a complete accessibility audit.

## This workspace's local PostgreSQL

Verification used a workspace-local binary distributed by `@embedded-postgres/windows-x64@18.7.0-beta.19` (the package has a beta suffix; the executable reports PostgreSQL 18.7). It is a verification tool, not an application dependency. The ignored `.tools/postgres/` directory contains the binary, SCRAM credentials, logs, and cluster. It listens only on `127.0.0.1:55432`. Local `backend/.env` already points to it; credentials are deliberately omitted from this README.

If restarting this existing local cluster, from root:

```powershell
# Check first: if already running, do not start another instance.
& .tools/postgres/package/native/bin/pg_ctl.exe -D .tools/postgres/data status
# Only if not running:
& .tools/postgres/package/native/bin/pg_ctl.exe -D .tools/postgres/data -l .tools/postgres/server.log -o '-h 127.0.0.1 -p 55432' -w start
# Stop when no longer needed:
& .tools/postgres/package/native/bin/pg_ctl.exe -D .tools/postgres/data -m fast -w stop
```

These files are local and do not accompany a clone; other developers should configure their own PostgreSQL instance.

## Troubleshooting and limits

- `python.exe` Windows alias fails: install Python or use a real interpreter's full path. This workspace used `C:\Users\User\AppData\Roaming\uv\python\cpython-3.12.16-windows-x86_64-none\python.exe`.
- API unavailable: start Uvicorn, verify the URL and exact CORS origin. Database unavailable: start PostgreSQL and check database name, port and credentials; the API must continue to return `503` rather than fake success.
- Port 5173 is already in use: first open the existing localhost page; the frontend may already be running. To restart, stop its original terminal with Ctrl+C before running `npm run dev` again. Do not switch ports without also updating CORS.
- Backend tests stalled under the restricted Windows execution sandbox during initial verification; they passed when run with permitted normal process access. Do not treat a stalled run as a pass.
- The installed Starlette version warns that its `httpx` TestClient support is deprecated in favor of `httpx2`; current tests pass. Review this before upgrading the test client.
- Do not run migration downgrade against a database containing useful data.
- Theme/language persist in localStorage when permitted; controls remain usable when storage is unavailable. Screen reader, keyboard-only and comprehensive accessibility audits remain future hardening work.

See [the consolidated Bahasa Indonesia report](docs/reports/PHASE_2_IMPLEMENTATION_REPORT.md) for actual evidence, limitations and acceptance criteria.
